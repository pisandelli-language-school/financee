## 2024-05-24 - N+1 Query in Concurrent/Looping Logic
**Learning:** Functions that perform database queries and are subsequently called inside loops or via `Promise.all` without internal caching create severe N+1 query bottlenecks. In this specific case, `resolveEffectiveDueDate` fetched non-business days on every call, leading to many duplicated queries when generating multiple installments or processing multiple entries concurrently.
**Action:** When creating utility functions that query relatively static database configuration (like business days), always implement a promise-based TTL cache. A promise-based cache (instead of just caching the data) is crucial because it ensures that concurrent calls fired at the same time (e.g. `Promise.all`) wait on the exact same database query promise rather than firing multiple simultaneous queries before the cache is populated.
